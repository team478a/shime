# SHIME 管理者・スタッフ操作マニュアル

更新日: 2026-07-31  
対象: SHIME 2026-08-08版  
想定端末: スマートフォン優先、必要に応じてPC

## 1. このマニュアルについて

SHIMEの管理画面を使い、イベントの初期設定、参加者管理、当日受付、席配置、
希望・結果確定、バックアップ出力を行うための手順である。

画面に表示される機能はログインしたスタッフの権限によって異なる。
権限がない機能は表示されない、または管理トップへ戻る。

本番画面で検証用データを入力せず、検証環境で本番参加者データを使用しない。

## 2. ログイン

1. 運営責任者から案内された管理画面URLを開く。
2. 「SHIME 運営ログイン」で次を入力する。
   - テナントコード
   - ログインID
   - パスワード
3. 「ログイン」を押す。
4. 管理トップに自分の表示名と権限が表示されることを確認する。

ログインできない場合は、入力内容、アカウント状態、対象テナントを確認する。
パスワードをチャットや共有資料へ貼り付けない。

## 3. 権限

| 権限 | 主な担当 |
|---|---|
| 受付担当 | 参加者確認、QR・手動受付、受付取消 |
| 運営担当 | 受付、運営進捗、CSV取込、席配置の編集、通常CSV出力 |
| 運営責任者 | イベント設定、席配置公開、結果確定、責任者限定CSV、診断公開 |
| システム管理者 | 全機能、管理者・権限、外部接続、イベント削除、結果確定取消 |

必要以上に強い権限を付与しない。受付スタッフには通常「受付担当」を使用する。

## 4. 管理トップ

管理トップでは、担当イベントごとに次のボタンを表示する。

- 「運営進捗」: 各工程の完了人数を確認
- 「当日受付」: QRまたは参加者検索で受付
- 「席配置」: 配置案の作成、調整、公開
- 「参加者・LINE連携」: 連携状態確認、本人連携リンク再発行
- 「設定・詳細」: イベント固有設定

スマートフォンでは横へスクロールせず、対象イベントのボタンを縦に選択する。
イベント名を必ず確認してから操作する。

## 5. イベント初期設定

### 5.1 推奨設定順

1. 下書きイベントを作成
2. 基本設定
3. 規約・プライバシー
4. 申込フォーム項目
5. Dream設定
6. 席案内5問
7. 診断テンプレート適用
8. テーブル・席マスター
9. 参加者導線
10. 設定チェック
11. 申込受付を開始

未確定項目がある間は下書きのまま保存できる。
受付開始に必要な設定が不足している場合、システムは受付開始を拒否する。

### 5.2 下書きイベント作成

1. 管理トップの「イベント作成」を開く。
2. イベントコード、イベント名、開始日時、定員などを入力する。
3. 「下書きイベントを作成」を押す。
4. 対象イベントの「設定・詳細」を開く。

イベント固有値を別イベントから推測して入力しない。
日時は日本時間で入力され、システム内部ではUTCで保存される。

### 5.3 基本設定

「イベント設定」→「基本設定」で次を確認する。

- イベント名、開始・終了日時
- 会場名、住所
- 定員
- 申込開始・締切
- Dream方式
- 希望入力方式、開始・締切
- 参加区分
- 席替え・会話ラウンド
- 保存期間、規約版
- イベント状態

状態は原則として前へ1段階ずつ進める。後戻りには理由と責任者権限が必要となる。
希望入力開始後は希望方式を変更しない。

### 5.4 設定チェック

「イベント設定」→「設定チェック」を開く。

- 「受付開始に必要な設定が揃っています」と表示されるまで各項目を設定する。
- 未確定項目は該当画面の「設定する」から修正する。
- 設定済みの場合も、日時、会場、定員、規約版を目視確認する。

表示上の「設定済み」は内容の事務的な正しさを保証しない。責任者が正式資料と照合する。

## 6. 規約・プライバシー

1. 「イベント設定」→「規約・プライバシー」を開く。
2. イベント規約またはプライバシーポリシーを選ぶ。
3. 版番号、タイトル、本文を入力して下書き保存する。
4. スマートフォン表示を確認する。
5. 内容と版番号を確認して公開する。

公開済み文書は直接編集しない。修正時は新しい版を作成する。
旧版への同意記録は保持される。
正式承認前の仮文面を本番イベントで公開しない。

## 7. 申込フォーム

### 7.1 項目設定

「イベント設定」→「申込フォーム項目」で表示名、入力種類、必須区分、
表示順、選択肢を設定する。

- 氏名、参加区分、規約同意、プライバシー同意などの保護項目は非表示にできない。
- 電話番号またはメールアドレスの少なくとも一方を表示する。
- テンプレートをコピーした後はイベント専用設定として保存される。

### 7.2 公開申込

参加者へは運営が発行した申込URLを案内する。
申込受付期間外の送信はサーバー側で拒否される。

### 7.3 CSV取込

1. 「参加者管理」→「CSV取込・重複確認」を開く。
2. UTF-8 CSVを選択する。
3. 全件反映または部分反映を選ぶ。
4. 正常、警告、エラー件数を確認する。
5. 行ごとの内容を確認後、「検証済みの行を申込みへ反映」を実行する。
6. 重複候補を「同一人物」「別人」「保留」から1件ずつ判定する。

システムは重複候補を自動統合しない。
再取込で受付、希望、結果を上書きしない。
CSV原本をチャットへ貼り付けない。

## 8. Dream・席案内5問・SHIME診断

### 8.1 Dream設定

「イベント設定」→「Dream設定」で必須、任意、既存Dream利用などの方式を設定する。

- 「必須（非公開可）」でも公開を強制しない。
- 任意の場合は参加者がスキップできる。
- AIを使用する場合も、固定文フォールバックを必ず保持する。
- 氏名、電話番号、メール、生年月日をAI用文面へ含めない。

### 8.2 席案内5問

「イベント設定」→「席案内5問」でイベント用質問票を作成または
テンプレートからコピーする。

- イベント開始後に利用中の質問票版を直接変更しない。
- 回答は席配置の計算に使用し、他参加者へ公開しない。
- 公開前に5問、選択肢、分析軸を確認する。

### 8.3 SHIME診断

1. テナント共通の「診断・カード管理」でカードと診断テンプレートを版管理する。
2. 公開済みテンプレートをイベントの「診断テンプレート適用」へコピーする。
3. 4分析軸、8感情、8カードが揃っていることを確認する。
4. 利用開始・終了日時を設定する。
5. 必要な場合だけ「SHIME診断を利用可能にする」をONにする。

公開済みテンプレートや画像を上書きしない。修正は新しい版を作成する。
参加者の診断回答と結果は他参加者へ公開されない。
外部AI生成は本版の診断処理では使用しない。

## 9. テーブル・席マスター

「イベント設定」→「テーブル・席マスター」を開く。

### 9.1 新規会場

1. 「かんたん自動生成」でテーブル記号、開始番号、卓数、1卓の席数を入力する。
2. 不均等な構成は「テーブルごとの詳細編集」で調整する。
3. 座席図、卓数、総席数、定員との差を確認する。
4. 「テーブル・席を保存」を押す。

### 9.2 既存会場

1. 「会場テンプレート・過去イベントからコピー」を開く。
2. コピー元を選ぶ。
3. 対象イベント専用に調整する。
4. 座席図を確認して保存する。

コピー元は変更されない。自動生成またはコピーだけではDBへ保存されない。
配置案の作成後は席マスターを置き換えられないため、先に確定する。

### 9.3 テンプレート管理

同じ会場構成を再利用する場合、「現在の構成をテンプレート保存」を使用する。
同名保存は上書きではなく新しい版になる。
アーカイブは新規利用対象から外す操作であり、過去イベントと履歴は削除されない。

## 10. 参加者導線

「イベント設定」→「参加者導線」を開く。

1. 有効にするステップを確認する。
2. 上下ボタンで表示順を調整する。
3. 公開前警告を解消する。
4. 「この順序を公開」を押す。

安全上の固定条件:

- Dreamと席案内5問はSHIME PASSより前
- 受付QRはSHIME PASS発行後
- SHIME診断は診断設定が有効な場合だけ公開可能
- 必須ステップ未完了時は後続ステップへ進めない

公開するまで現在の参加者導線は変わらない。

## 11. LINE本人連携

### 11.1 通常

申込完了後、参加者が同じスマートフォンから「LINEで本人連携へ」を開く。

### 11.2 リンク再発行

1. 対象イベントの「参加者・LINE連携」を開く。
2. 参加者番号の前方一致または氏名の一部で検索する。
3. 未連携参加者の「リンクを再発行」を押す。
4. 対象者を確認する。
5. 表示された新URLを、その画面を閉じる前にLINEで開くかコピーする。

再発行すると旧URLは即時失効する。新URLは72時間有効である。
連携済み参加者には再発行できない。
本人以外のLINEアカウントで開かない。

## 12. 当日受付

### 12.1 受付開始前

- スタッフ全員が自分のアカウントでログインできることを確認する。
- 受付対象イベント名を確認する。
- カメラ権限、通信状態、予備充電、手動検索を確認する。
- 紙の受付表を責任者管理で準備する。

### 12.2 QR受付

1. 管理トップから対象イベントの「当日受付」を開く。
2. QR読取を開始する。
3. 参加者のSHIME PASSに表示されたQRを読み取る。
4. 表示された参加者番号・氏名・状態を確認する。
5. 「受付を確定」を押す。
6. 受付番号を参加者へ案内する。

QR読取だけでは受付は確定しない。必ず確認画面で対象者を確認する。

### 12.3 手動受付

QRを表示できない場合:

1. 参加者番号の先頭1文字以上、または氏名の一部を入力する。
2. 「参加者確認」を押す。
3. 候補カードから対象者を選ぶ。
4. 参加状況と受付状態を確認する。
5. 受付を確定する。

電話番号や生年月日を聞き取って完全一致入力する必要はない。
候補が複数の場合は、参加者番号や本人申告を追加確認する。

### 12.4 取消・再受付

受付取消は理由プリセットを選び、必要に応じて補足を入力する。
「その他」は補足必須である。
取消後の再受付では最初の受付番号を維持する。
二重受付警告が出た場合は新しい受付を作らず、現在状態を確認する。

## 13. 運営進捗

「運営進捗」で次の完了人数を確認する。

- 申込受領、参加確定、参加者登録
- LINE本人連携
- Dream入力完了
- 席案内5問提出
- 当日受付
- 席配置
- 希望提出
- 結果確定、通知送信・失敗

進捗画面は個人名や回答内容を表示せず、工程別人数を確認する画面である。
不足者の確認は、権限のある各詳細画面で行う。

## 14. 席配置

1. 受付状況、欠席、接触回避情報を確定する。
2. 「新しい配置案を生成」を押す。
3. 配置済み・未配置人数と警告を確認する。
4. 必要な参加者を短い検索で絞り込む。
5. 席変更、未配置化、席ロックを行う。
6. 変更件数を確認し「変更を保存」を押す。
7. テーブル別座席図を確認する。
8. 運営責任者がイベント名、配置済み人数、未配置人数を確認する。
9. 「内容を確認して公開」を押す。

未保存変更がある間は公開しない。
欠席変更後は古い案を修正せず、新しい配置案を生成する。
公開前の下書きは参加者へ表示されない。

## 15. 希望入力・結果確定

### 15.1 希望入力

1. 席配置公開後、「希望・結果確定」を開く。
2. 期間と希望方式を再確認する。
3. 「希望入力を開始」を押す。
4. 提出人数を確認する。
5. 締切時刻後、「希望入力を締切」を押す。

一方希望、順位、任意メモを相手へ表示しない。

### 15.2 結果確定

1. 双方希望候補を確認する。
2. 候補を承認、辞退、保留に分類する。
3. 複数成立不可の設定では競合をすべて解消する。
4. 保留と未処理が0件であることを確認する。
5. 対象人数と成立組数を確認する。
6. 運営責任者が「人数を確認して公開」を押す。

システムは結果を自動公開しない。
確定取消はシステム管理者だけが理由を入力して実行できる。

### 15.3 通知

1. 通知対象数と文面をプレビューする。
2. 成立・不成立・成立組数を確認する。
3. 同じ件数を再確認して通知を予約する。
4. 失敗件数を確認し、原因解消後に再送する。

本番通知は責任者の明示確認前に送信しない。

## 16. CSVバックアップ

「結果・記録」→「CSVバックアップ」から次を出力できる。

- 参加者一覧
- 受付一覧
- 公開済み席表
- 進捗一覧
- 確定結果

責任者権限では、一方希望、順位、非公開メモを含む「希望詳細」も出力できる。
希望詳細は特に機密性が高いため、必要な責任者だけが取り扱う。

CSVは端末内へ放置せず、利用後に安全な保管先へ移動または削除する。

## 17. 管理者・外部接続

### 17.1 管理者・権限

システム管理者は「管理者・権限」からスタッフを追加・編集できる。

- パスワード、権限、状態変更時は対象者の既存セッションが失効する。
- 自分自身のシステム管理者権限を外せない。
- 最後の有効なシステム管理者を無効化できない。

退職・担当終了したアカウントは速やかに無効化する。

### 17.2 外部接続・運用設定

システム管理者は次を設定できる。

- LINE Login、LIFF、Messaging API
- 独自ドメイン確認、Healthcheck
- 監視、定期通知ジョブ
- 通知テンプレート
- OpenAI接続設定

秘密値は保存後に再表示されない。空欄保存は既存値を維持する。
LINE、AI、通知ジョブは接続試験完了まで有効化しない。

## 18. エラー時の対応

### 18.1 「検索しても反応がない」

- 「検索中」の表示を確認する。
- 参加者番号の先頭1文字、または氏名の一部で再検索する。
- イベント名と検索対象を確認する。
- 通信エラー表示があれば再読込する。
- ログイン期限切れの場合は再ログインする。

### 18.2 「候補なし」

- 参加者番号と氏名の両方を試す。
- 参加者が対象イベントに登録済みか確認する。
- 絞り込み条件を「すべて」に戻す。
- CSV取込が検証だけで、反映未実行になっていないか確認する。

### 18.3 QRが読めない

- 参加者にQRを明るく大きく表示してもらう。
- 参加者が「QRを再発行」した場合、古いQRは使用しない。
- 手動受付へ切り替える。

### 18.4 通信障害

- 同じ確定ボタンを連打しない。
- 再読込後に現在状態を確認する。
- 受付は紙の受付表、席案内は最新の公開済み席表へ切り替える。
- 復旧後、紙運用分を責任者確認のもと反映する。
- 発生時刻、対象工程、影響件数、対応者を記録する。

## 19. 情報管理

次を画面共有、チャット、一般共有フォルダへ掲載しない。

- 管理者ID・パスワード
- Supabase接続情報、APIキー
- LINEトークン、本人連携URLのトークン部分
- 受付QRの生コード
- 本番参加者の氏名、連絡先、生年月日
- 一方希望、順位、非公開メモ
- 非公開Dream、質問回答、診断回答

スタッフは共用アカウントを使わず、自分のアカウントで操作する。

# SHIME マッチ後チャット 有効化ゲート

作成日: 2026-08-07
対象: マッチ成立後チャット
現在の本番状態: migration 0021〜0023適用済み、機能OFF、設定・room・message 0件

## 1. 目的

マッチ後チャットを、規約や通報体制が不明なまま誤って公開しないための確認手順です。実参加者を使わず、隔離UATイベントと合成参加者だけで確認します。

## 2. 有効化前に必須の設定

管理画面の「マッチ後チャット設定・通報対応」で、次のすべてを登録します。

1. 利用時間
2. 1分あたり送信上限
3. 1通の最大文字数
4. 本文保持日数
5. 同意規約の版
6. 参加者へ全文表示する正式なチャット利用規約本文
7. 通報対応責任者
8. 合成参加者UATの確認記録

いずれかが未設定の場合、画面・API・DBの各境界で機能ONを拒否します。規約本文や責任者名は開発側で推測せず、主催者が正式な内容を入力します。

## 3. 合成データUAT

### 準備

- 隔離UATイベントを使用する。
- 実在しない合成参加者を2名用意する。
- 2名を成立ペアとしてmanagerが確定し、結果を公開する。
- スマートフォンまたは分離したブラウザセッションを2つ用意する。
- 本番参加者へのLINE通知は送信しない。

### 操作

1. UATイベントだけに正式なテスト用規約、保持日数、通報担当を設定する。
2. UATイベントで確認欄へチェックする場合は、これはテスト実施の承認記録として扱い、UATイベントだけをONにする。本番イベントの確認欄は、以下の確認をすべて完了するまでチェックしない。
3. 参加者Aが結果画面からチャットを開く。
4. 正式規約本文が全文表示され、規約版が一致することを確認する。
5. 参加者Aだけが同意した状態では送信できず「相手の同意待ち」になることを確認する。
6. 参加者Bも同意し、双方同意後だけroomが開くことを確認する。
7. A→B、B→Aで1通ずつ送信し、相手側へ表示されることを確認する。
8. 最大文字数と1分あたり送信上限を超えた送信が拒否されることを確認する。
9. 同じ送信を再試行しても二重登録されないことを確認する。
10. 参加者Aが通報し、双方の画面で即時にチャットが停止することを確認する。
11. 管理画面の通報一覧に参加者番号・分類・補足だけが表示され、チャット本文が表示されないことを確認する。
12. 担当者が「確認中」から「対応済み」へ更新できることを確認する。
13. 匿名集計で少人数抑制が働き、個人や本文を推測できないことを確認する。
14. UAT終了後、UATイベントのチャットをOFFへ戻す。

期限切れ、暗号化、tenant/event分離、cross-participant拒否、冪等性、削除jobは自動テストでも確認します。実時間72時間を待つ代わりに、固定時刻の単体・結合テストで期限境界を検証します。

## 4. 中止条件

次のいずれかが発生したらONのまま続行しません。

- 規約本文が表示されない、または版が一致しない。
- 片方だけの同意で送信できる。
- 当事者以外がroom・本文・通報へアクセスできる。
- blockまたは通報後も送信できる。
- 管理画面やログへ本文、Dream、希望順位、感情回答が露出する。
- tenant/event境界を越えたデータが見える。
- 通報担当者と当日の対応方法が決まっていない。

## 5. 本番イベントのGo条件

- 正式な規約本文と版を主催者が承認済み。
- 本文保持日数を主催者が承認済み。
- 通報対応責任者、確認頻度、緊急連絡方法を主催者が決定済み。
- 上記UATを合成参加者だけで完了し、失敗項目が0件。
- migration 0024をバックアップ後に適用し、対象releaseをデプロイ済み。
- 本番イベントをONにする操作について別途明示承認済み。

現時点では、規約内容・保持日数・責任者・UAT結果が確定していないため、本番イベントはOFFを維持します。

# SHIME 参加者導線・受付番号・公開プロフィール方針 V1

更新日: 2026-07-24

## 確定事項

- 2026年8月8日の必須導線に決済を含めない。
- 既存の参加者番号は変更しない。
- 当日受付時に、参加区分ごとの受付番号を別途採番する。
- 受付取消後の再受付では、最初に採番した受付番号を維持する。

## 参加者導線の管理方式

管理者がイベントごとに次のステップの順序と必須・任意を設定できる方式を推奨する。

- Dream
- 席案内5問
- SHIME診断
- SHIME PASS・受付QR
- 当日受付

ただし、単なる自由並び替えにはしない。画面上の表示順と、システム上の完了条件を分け、公開前に依存関係を検証する。

### 変更できない安全条件

- 申込と本人連携は参加者向け機能より先に完了する。
- 受付QRはSHIME PASS発行後にのみ発行する。
- 当日受付は有効なQRまたは権限のあるスタッフによる手動確認で行う。
- 席案内5問は席配置作成までに完了する。
- 必須ステップが未完了の場合、後続ステップへ進めない。
- 公開済みイベントの導線はスナップショットとして固定し、テンプレート編集で変化させない。

### 8月8日の推奨初期順序

1. 申込
2. LINE本人連携
3. Dream
4. 席案内5問
5. SHIME PASS・受付QR
6. 当日受付
7. SHIME診断
8. イベント本編

SHIME診断を受付前に実施する運用も設定可能にするが、8月8日の初期値は受付後を推奨する。会場で未回答者をスタッフが把握しやすく、事前離脱の影響を減らせるためである。

### 管理画面案

- 上下移動ボタンを主操作とし、スマートフォンでドラッグ操作を必須にしない。
- 各ステップに「必須」「任意」「非表示」を設定する。
- 「公開前チェック」で依存関係、未設定フォーム、QR発行条件を表示する。
- 公開後の変更は新しい導線バージョンを作り、明示確認後に反映する。
- 変更履歴には操作者、日時、変更前後、対象イベントを記録する。

## 受付番号

受付番号は参加者番号とは別の当日運用用番号である。

- スコープ: テナント・イベント・参加区分
- 表示例: `グループA1番`
- 保存項目: 参加区分コード、参加区分名のスナップショット、区分内連番
- 採番時点: 受付確定時
- 欠番: 再利用しない
- 取消・再受付: 同じ番号を維持
- 同時受付: DBトランザクションと一意制約で重複を防止

参加区分は婚活固有の「男性・女性」に固定せず、イベント設定の区分を利用する。これによりSHIME OSの他用途へ横展開できる。

## Love Passport 公開プロフィール提案

### 保存方式

本人確認情報や申込情報を直接公開せず、公開専用プロフィールを別データとして保存する。

公開候補:

- 表示名
- 年代（生年月日そのものは保存・公開しない）
- 職業カテゴリ
- 趣味・関心
- 休日の過ごし方
- 自己紹介

保存単位はテナント・イベント・参加者とし、下書き版と公開版を分ける。更新時は新しい版を作成し、過去版を監査用に保持する。

### 公開方式

- 初期状態は非公開。
- 本人がプレビューを確認し、同意文書の版を確認して明示公開する。
- 公開後も本人が非公開へ戻せる。
- 公開期間はイベント当日の指定時間帯に限定する。
- 公開対象は同一イベントで受付済みの参加者に限定する。
- 公開項目は管理者が承認したホワイトリストから選び、個人情報や自由な内部項目を公開対象にしない。

### 閲覧方式

一覧で全参加者を列挙せず、相手から伝えられた受付番号を入力または選択して閲覧する方式を推奨する。

閲覧条件:

- 閲覧者と対象者が同じテナント・イベントに所属する。
- 両者が受付済みである。
- 対象者がプロフィールを公開中である。
- 公開時間内である。
- 閲覧回数制限と監査ログを適用する。

受付番号だけでAPIへ直接アクセスできないよう、参加者セッションとイベント権限を必須にする。検索結果には許可された公開項目だけを返す。

### AIの扱い

AIは自己紹介文の下書き支援に限定し、外部AIが利用できない場合も手入力で完結できるようにする。AI生成文は本人の確認と明示公開なしに公開しない。

## 実装順序

1. 受付番号のDB・受付処理・表示・CSV対応
2. 参加者導線の版管理スキーマと公開前検証
3. スマートフォン向け導線設定画面
4. 公開プロフィールの下書き・同意・公開・取消
5. 受付番号による限定閲覧
6. 権限・監査・期間制限・負荷試験
